## 一、踩坑记录

| 现象 | 原因 | 解决 |

| 装完 Git 后,终端敲 `git` 报"无法将 git 项识别为 cmdlet" | PATH 环境变量只在**新建**的终端里生效 | 关掉终端重新开一个 |

| `git clone` 报 `Repository not found` | 仓库名拼错了(`hijja` 写成了别的) | 对着仓库页面核对拼写 |
| `cv2.imread` 返回 `None`,后面全崩 | 路径里有中文,OpenCV 读不了 | 用 `cv2.imdecode(np.fromfile(path, np.uint8), ...)` |
| matplotlib 的标题里中文变成方框 | 默认字体不含中文字形 | `plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei"]` |
| 脚本跑一半突然崩,报 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'` | 打印语句里用了 `✓`,而这个符号不在 Windows 默认的 GBK 编码里 | 脚本里只用中文 + ASCII 符号,`✓` 换成 `OK` |
| 把 Python 代码粘进终端,报"所在位置 行:8 字符: 24" | 那是 **PowerShell** 的报错格式,终端不认识 Python 语法 | 代码只能放进 `.py` 文件或交互窗口,不能粘进终端 |

| 处理完一段视频再想从头读一遍,读到的全是空帧 | `VideoCapture` 的读取指针停在末尾,**不会自动回到开头** | 重新 `cv2.VideoCapture(路径)`,或用 `cap.set(cv2.CAP_PROP_POS_FRAMES, 0)` |
| 写出的视频是 0 字节或打不开 | `VideoWriter` 的尺寸/fps 和写入的帧不一致 | 尺寸必须等于 `(帧的宽, 帧的高)`,fps 用原视频的 `CAP_PROP_FPS` |
| 单元格运行报 `NameError: name 'img' is not defined` | 跳过了定义变量的那一格;变量只存在于内存里,必须由上往下建立 | 点出错那一格上方的 `Run Above`,或从第一格依次运行 |
| 脚本里出现 `²` `✓` 这类符号导致 `UnicodeEncodeError` | 这些字符不在 Windows 的 GBK 编码里 | 只用中文 + ASCII 符号;打印里写"平方像素"而不是"像素²" |

## 二、API 卡片

格式:**函数名 | 一句话 | 一个例子 | 一个坑**。每学一个新函数就加一行。

| 函数 | 一句话 | 例子 | 坑 |
|---|---|---|---|
| `cv2.imread` | 读图,返回 ndarray | `img = cv2.imread(path)` | 读不到**不报错**,只返回 `None`;路径含中文会失败 |
| `cv2.imwrite` | 保存图片 | `cv2.imwrite("a.png", img)` | 目标目录不存在不会自动创建,要先 `os.makedirs` |
| `cv2.split` | 拆成 B、G、R 三个单通道 | `b, g, r = cv2.split(img)` | 等价于 `img[:, :, 0/1/2]`,后者更直观 |
| `cv2.cvtColor` | 颜色空间转换 | `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` | `BGR2RGB` 和 `RGB2BGR` 是**同一个操作**(都是倒序) |
| `cv2.cvtColor`(转灰度) | 灰度化 | `cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)` | 是加权平均 `0.114B+0.587G+0.299R`,不是三通道取平均 |
| `Image.open` | Pillow 读图 | `im = Image.open(path)` | `im.size` 是 **(宽, 高)**,和 OpenCV 的 `(高, 宽)` 相反 |
| `Image.split` | Pillow 拆通道 | `r, g, b = im.split()` | 顺序是 **R、G、B**,和 `cv2.split` 相反 |
| `cv2.resize` | 缩放 | `cv2.resize(img, (w2, h2))` 或 `fx=0.5` | 尺寸参数是 **(宽, 高)**,和 shape 相反;缩小默认插值不是最优 |
| `cv2.warpAffine` | 按 2×3 矩阵变换整幅图 | `cv2.warpAffine(img, M, (w, h))` | 第三个参数是**输出画布大小**,画布不会自动变大,旋转时四角会被裁 |
| `cv2.getRotationMatrix2D` | 造一个旋转矩阵 | `M = cv2.getRotationMatrix2D((cx, cy), 30, 1.0)` | 正角度在屏幕上**逆时针**;换画布时自己补偏移 |
| `cv2.flip` | 镜像 | `cv2.flip(img, 1)` | `1` 水平 / `0` 垂直 / `-1` 两个都翻(等价转 180°) |
| `cv2.rotate` | 转 90 的整数倍 | `cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)` | 干净无黑边;但 90° 会让**宽高互换** |
| `np.array_equal` | 判断两个数组是否完全相同 | `np.array_equal(a, b)` | 用它做"两个库读的是不是同一批数据"的硬证据 |
| `cv2.GaussianBlur` | 高斯模糊去噪 | `cv2.GaussianBlur(gray, (5,5), 0)` | 必须在边缘检测**之前**做,否则噪声会被当成假边缘 |
| `cv2.Canny` | 边缘检测 | `cv2.Canny(blur, 50, 150)` | 两个阈值是低/高门限,经验比例 1:2~1:3;输出是断断续续的边缘 |
| `cv2.morphologyEx` | 形态学运算 | `cv2.morphologyEx(edges, cv2.MORPH_CLOSE, kernel, iterations=3)` | **闭运算**把断开的边缘连起来,是轮廓检测的关键一步 |
| `cv2.findContours` | 找轮廓 | `contours, hierarchy = cv2.findContours(bin_img, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)` | **会修改传入的二值图**,要先 `.copy()`;统计总面积必须用 `RETR_EXTERNAL` |
| `cv2.contourArea` | 轮廓面积 | `cv2.contourArea(c)` | 单位是平方像素;孔洞也会返回正数,所以不能拿 `RETR_LIST` 的结果求和 |
| `cv2.arcLength` | 轮廓周长 | `cv2.arcLength(c, True)` | 第二个参数**必须传 True**(表示闭合),传 False 会少算最后一段 |
| `cv2.boundingRect` | 外接矩形 | `x, y, w, h = cv2.boundingRect(c)` | 顺序是 **(x, y, 宽, 高)**,和 shape 的 (高, 宽) 不同 |
| `cv2.VideoCapture` | 读视频 | `cap = cv2.VideoCapture(path)` | 指针不会自动回到开头;`cap.read()` 返回 `(是否成功, 帧)` |
| `cv2.VideoWriter` | 写视频 | `cv2.VideoWriter(path, cv2.VideoWriter_fourcc(*"mp4v"), fps, (w, h))` | 尺寸和 fps 必须与写入的帧一致,否则输出是 0 字节 |
| `cv2.absdiff` | 算两帧的绝对差 | `cv2.absdiff(prev, cur)` | 帧差法的核心就这一行 |
| `cv2.createBackgroundSubtractorMOG2` | 建背景模型 | `fgbg = cv2.createBackgroundSubtractorMOG2(history=500, varThreshold=16, detectShadows=True)` | 开启阴影检测后**阴影像素是 127**,要自己清成 0;前几十帧是预热期 |
| `fgbg.apply` | 用背景模型算前景掩码 | `mask = fgbg.apply(frame)` | 需要按顺序逐帧调用,不能跳帧 |

### 记不住的时候怎么想

- **shape 的三个数字**:`(高, 宽, 通道数)`。想象一张纸:先数行、再数列。
- **单通道图长什么样**:灰度图,两个维度。哪块亮,就说明那块该通道的数值大。
- **BGR vs RGB**:OpenCV 是历史原因用 BGR,Pillow 和 matplotlib 用 RGB。跨库使用**先转一次**。

## 三、核心概念卡片

### 卡片 1:一张图在内存里长什么样

- shape 是 `(高, 宽, 3)`,dtype 是 **uint8**
- `uint8` = 无符号 8 位整数 = 取值范围 **0~255**。这不是"格式化",是数据类型,决定每个数字能存多大
- **坑**:uint8 会溢出。`np.array([250], dtype=np.uint8) + 10` 的结果是 **4**,不是 260
- 所以调整亮度、做数据增强时,通常要先把图转成 `float` 算,算完再转回 `uint8`

### 卡片 2:BGR 与 RGB 的对应关系

| 数组里的位置 | 第 0 个 | 第 1 个 | 第 2 个 |
|---|---|---|---|
| **OpenCV** 认为它是 | B 蓝 | G 绿 | R 红 |
| **Pillow / matplotlib** 认为它是 | R 红 | G 绿 | B 蓝 |

**记忆**:红色,OpenCV 放在**最后**一位,Pillow 放在**最前**一位。

**证明**(对任何图片都成立,不依赖图片内容):

```python
np.array_equal(img_bgr[:, :, ::-1], np.asarray(Image.open(path)))   # True
```

> 验证通道顺序时**必须挑彩色像素**。灰色像素三个数相等,看不出顺序差别。

### 卡片 3:图像坐标系 —— y 轴朝下(这是总钥匙)

原点在**左上角**,x 向右增大,y **向下**增大。

**这一条规律解释了三个现象:**

1. 平移时 `ty` 为正 = 图片**往下**移
2. 旋转的正角度 = 屏幕上**逆时针**
3. OpenCV 的旋转矩阵 `[[cos, sin], [-sin, cos]]` 和数学课本 `[[cos, -sin], [sin, cos]]` **符号相反**

### 卡片 4:2×3 仿射矩阵的六个位置

```
[[a, b, tx],
 [c, d, ty]]
```

| 位置 | 管什么 |
|---|---|
| 对角线 `(0,0)` `(1,1)` | **缩放** |
| 非对角线 `(0,1)` `(1,0)` | **旋转 / 剪切**(让两个方向互相影响) |
| 第 3 列 | **平移** |
| 想要纯缩放 | 非对角线必须是 **0** |

**读法**:把它念成两条公式

```
新 x = a·x + b·y + tx
新 y = c·x + d·y + ty
```

**常见矩阵一览**:

| 变换 | 矩阵 |
|---|---|
| 恒等(什么都不做) | `[[1,0,0],[0,1,0]]` |
| 平移 | `[[1,0,tx],[0,1,ty]]` |
| 旋转 θ | `[[cos,sin,tx],[-sin,cos,ty]]` |
| 剪切 k | `[[1,k,0],[0,1,0]]` |
| 缩放 sx, sy | `[[sx,0,tx],[0,sy,ty]]` |

**"仿射"是什么意思**:守规矩的变换。三条规矩 —— 直线还是直线、平行线还是平行、比例不变。所以矩形可以变成任意**平行四边形**,但永远变不成梯形(那是透视变换,要 3×3 矩阵)。

**为什么必须是 2×3**:2×2 矩阵做不了平移(矩阵乘法永远把原点映射到原点),加一列平移量就补上了。

**最省事的理解方式**:只看四个角。**四个角搬到哪,整张图就跟到哪** —— 别去纠结取景框外的中间过程。

### 卡片 5:自查工具 —— 行列式 det

```
det = a*d - b*c
```

- `det > 0`:面积被放大 `|det|` 倍(纯缩放 1.5 倍 → `1.5² = 2.25`)
- `det < 0`:**图像被翻转了**,说明你不小心写进了负号

### 卡片 6:"以中心为基准"都要补偿平移

想让图像中心保持不动,就必须在线性部分之外**补一个平移量**:

| 变换 | 补偿量 |
|---|---|
| 缩放 sx、sy | `tx = cx(1-sx)`,`ty = cy(1-sy)` |
| 旋转到新画布 | `tx += new_w/2 - w/2`,`ty += new_h/2 - h/2` |

`cv2.getRotationMatrix2D` 就是在替你算旋转那部分。

> **为什么旋转还要算新画布**:warpAffine 的输出画布原点固定在左上角 (0,0),不会自动居中。画布变大后,旋转轴还停在旧坐标上,图就会偏向一角。

### 卡片 7:缩放的插值方式怎么选

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| **缩小** | `INTER_AREA` | 区域平均,专门为缩小设计;用默认插值会出现摩尔纹 |
| 放大 | `INTER_LINEAR` | 双线性,平滑,是默认值 |
| 放大追求质量 | `INTER_CUBIC` | 三次插值,更平滑,更慢 |
| 想要马赛克 | `INTER_NEAREST` | 直接复制最近的像素,最粗糙 |

> 名字的直觉靠不住:`nearest` 才是那个有方块马赛克的;`cubic` 是"三次多项式",不是"立方块"。

### 卡片 8:翻转与旋转该怎么选

| 需求 | 用什么 |
|---|---|
| 镜像 | `cv2.flip(img, 1/0/-1)` |
| 90° / 180° / 270° | `cv2.rotate`,干净、无黑边(注意 **90° 会宽高互换**) |
| 任意角度 | `getRotationMatrix2D` + `warpAffine`,要自己算画布和偏移 |

`flip(-1)` 等价于 `ROTATE_180`(实测 `np.array_equal` 为 `True`)。

### 卡片 9:路径处理的标准写法

```python
PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
IMAGE_FILE = os.path.join(PROJECT_ROOT, "data", "example1.jpg")
```

从里往外读:`__file__`(脚本路径) → `abspath`(转绝对路径) → `dirname`(去掉文件名,剩 `src`) → `dirname`(再去一层,剩项目根目录)。

**作用**:让脚本**不依赖"你在哪个目录下运行"**。写相对路径 `data/xxx.jpg` 时,在 `D:\hijia` 下能跑、在 `D:\hijia\src` 下就找不到;用这个套路从哪跑都对。

### 卡片 10:轮廓检测的流水线

```
灰度 → 高斯模糊去噪 → Canny 边缘 → 形态学闭运算 → findContours → 算面积周长
```

**每一步为什么必要:**

| 步骤 | 为什么 |
|---|---|
| 去噪 | Canny 找的是"梯度变化剧烈的地方",噪声本身就是剧烈变化,不去掉会变成假边缘 |
| Canny | 图的灰度分布太集中时(如飞机与天空),阈值分割会把两者切到一起,只能走边缘这条线 |
| **闭运算** | Canny 的边缘是断的,不连起来轮廓就不闭合,一个物体会被拆成几十个碎轮廓 |
| `RETR_EXTERNAL` | 只取最外层。用 `RETR_LIST` 会把内部孔洞也当轮廓,面积被重复累加 |

**面积和周长:**

```python
cv2.contourArea(c)        # 面积,单位平方像素
cv2.arcLength(c, True)    # 周长,True 表示闭合(必须传 True)
```

**外接矩形的三个用处**:①验证轮廓抓得对不对 ②产生可写进报告的数字(还能算"填充率") ③目标检测和追踪用的就是这种矩形框。

### 卡片 11:两种运动目标检测的判据(题四)

| | 判据 | 优点 | 天生的短板 |
|---|---|---|---|
| **MOG2 背景减除** | 和**背景模型**比 | 物体只要还在场景里就能持续检出;形状贴合物体 | 需要预热(前几十帧不可用);计算量大(实测约 61 fps) |
| **帧差法** | 和**上一帧**比 | 实现简单、速度快(实测约 131 fps,快 2 倍) | 快 → 拖影;慢 → 漏检;**停 → 消失** |

**实测对比(高速公路车流视频)**:MOG2 平均 5.80 个框,帧差法 6.84 个 —— 帧差法多出来的框,大多是同一个目标被拖影切成两半,不是真的多了一辆车。帧差法的框总面积也更大(31705 vs 29168 平方像素),同样是拖影撑大的。

**一句话记住区别**:**比"上一帧"还是比"背景"**,决定了物体停下来之后还在不在。
